# Testing Strategy

Testing runs from cheapest to most realistic. Every layer is automated except the physical acceptance test.

```
L1 unit (pytest, g++)  ->  L2 end-to-end digital twin  ->  L3 ROS 2 build/test (colcon)  ->  L4 Gazebo  ->  L5 HIL bench  ->  L6 AtomQuest acceptance run
```

## L1. Unit tests

### Python: `tests/` (pytest, about 90 s including end-to-end)
```bash
python -m pytest tests -q
```
| File | Covers |
|---|---|
| `test_protocol.py` | CRC16-CCITT check value `0x29B1`, COBS vectors, framing, stream decoder, corruption rejection, telemetry layout (25 B) |
| `test_kinematics.py` | Wrap-angle, diff-drive inverse, arc integration, encoder odometry |
| `test_mapping_planning.py` | Ray integration, wall-echo rejection, wall band, dilation, A* detour and unreachable cases, boustrophedon serpentine, frontier pockets |
| `test_behaviour.py` | Safety levels, side-wall corridor rule, FSM legal and illegal transitions, adaptive suction, battery (pitch numbers), scoring, perception projection and mock detector |

### C++ firmware logic: `firmware/esp32s3_base_controller/test_host` (322 checks)
```powershell
# Windows PowerShell / cmd (MSYS2 UCRT64 g++ 16.2)
cd firmware\esp32s3_base_controller\test_host
g++ -std=c++17 -O2 -Wall -Wextra -Werror "-I../lib/chotu_logic/src" test_chotu_logic.cpp -o test_chotu_logic.exe
.\test_chotu_logic.exe          # -> chotu_logic host tests: 322 passed, 0 failed
```
```bash
make -C firmware/esp32s3_base_controller/test_host   # Linux / CI
```
The Python and C++ suites assert the **same byte vectors**, generated by `chotu_core/protocol.py`. That proves the firmware and the ROS bridge agree on the wire format.

> Git Bash note: the MSYS2 UCRT64 `g++` can fail silently from Git Bash's MSYS environment. Use PowerShell, cmd or the MSYS2 UCRT64 shell.

## L2. End-to-end digital twin: `tests/test_simulation_e2e.py`

Each case is a full 5-minute mission in a randomised room, using the real `CleaningMission` with sensor noise and odometry drift.

| Assertion | Threshold |
|---|---|
| Robot returns to the dock | required |
| Dock-to-dock time | ≤ 300 s |
| Final dock error | < 6 cm |
| Coverage of reachable floor | ≥ 65 % |
| Collisions | ≤ 5 |
| Cable incidents (with vision) | 0 |
| Projected AtomQuest score | ≥ 70 |
| Vision ablation | incidents(vision) < incidents(no vision) |
| Adaptive suction | > 5 % energy saved |

Benchmark and ablation:
```bash
python bot_simulation/run_simulation.py --benchmark 20 --headless --json bench.json
python bot_simulation/run_simulation.py --benchmark 20 --headless --no-vision
python bot_simulation/record_demo.py      # screenshots + MP4s + benchmark chart + metrics JSON
```

## L3. ROS 2 build and tests (Docker or WSL)
```bash
bash scripts/build_ros_docker.sh
# = rosdep install + colcon build --symlink-install + colcon test --packages-select chotu_base
```
Checks after the build:
```bash
ros2 interface show chotu_interfaces/msg/CleaningStatus
ros2 launch chotu_description description.launch.py rviz:=true     # model renders, TF tree ok
xacro ros2_ws/src/chotu_description/urdf/chotu.urdf.xacro > /tmp/chotu.urdf && check_urdf /tmp/chotu.urdf
```

## L4. Gazebo integration
```bash
ros2 launch chotu_bringup sim.launch.py rviz:=true vision:=false
ros2 topic hz /range/center          # ~17 Hz
ros2 topic echo /chotu/status --once # state progresses UNDOCK -> SCAN -> COVER ...
ros2 run tf2_tools view_frames       # odom -> base_footprint -> base_link -> sensors
```
Pass criteria: the robot leaves the dock, builds `/map` (view it in RViz), never touches the walls or box and bin models, and returns to the dock before T+300 s.

## L5. Hardware-in-the-loop bench (robot on blocks)

| Step | Command / action | Expected |
|---|---|---|
| 1 Link | `ros2 topic hz /odom` | 50 Hz, no CRC warnings |
| 2 Watchdog | Stop the bridge container | Wheels and vacuum stop within 0.3 s, watchdog flag set |
| 3 Wheel PID | `ros2 topic pub /cmd_vel geometry_msgs/Twist "{linear: {x: 0.2}}" -r 10` | Wheel speed from /odom 0.2 ± 0.02 m/s |
| 4 Sensors | Hand at 20 cm in front of each sensor | `/range/*` reads 0.20 ± 0.02 m |
| 5 Safety | Hand at 4 cm in front, then cmd_vel forward | Firmware refuses forward motion |
| 6 Bump | Tap the chassis | `/chotu/bump` true for one cycle |
| 7 Suction | `ros2 topic pub /chotu/actuators chotu_interfaces/msg/Actuators "{suction: 0.55, brush: 1.0}"` | Vacuum in ECO, no brown-out on the Pi |
| 8 Camera | `ros2 topic echo /chotu/detections` with a cable in view | `power_cable`, action `avoid` |

## L6. Acceptance: AtomQuest dry run on the real floor

1. Build a 10 ft × 10 ft area with 2 boxes, 1 chair, 1 bin and 1 cable, and place the dock on the south wall.
2. Weigh the garbage per type (dust, paper, hair, wrappers, wire strands) and scatter it.
3. Start the mission with the `/chotu/start_mission` service and the stopwatch together.
4. Record: docked yes/no, time, collisions, restarts, and the collected mass per type (weigh the container contents).
5. Compute the score with `chotu_core.scoring.score(RunResult(...))` and compare it with the simulator's prediction for a similar layout. If the coverage error is above 10 %, recalibrate the simulator noise (`engine.py`: wheel slip, gyro bias, sonar noise).
